**Gradient text rule:** when text overlays a linear gradient (hero, banners), `check-contrast` generates **two pairs** — one against the lightest stop and one against the darkest. The lightest stop is the worst case for dark text on a light-to-dark gradient; both must pass. Do not validate against the gradient's "average" colour.

## Contrast & Affordance Audit Checklist

- [ ] Hero sections — all text uses `hero-text` (solid, no opacity)
- [ ] Gradient text verified at the **lightest stop**, not just the average
- [ ] Active tabs/nav — use `text-primary` (not a low-contrast variant) on light backgrounds
- [ ] Status badges — use darker text variants in light mode with dark-mode overrides
- [ ] Status badges have no hover, focus, or `cursor:pointer` (they are not interactive)
- [ ] Normal text on panels — use `text-strong` or `text-soft`; never `text-faint` for meaningful content
- [ ] Every interactive token has hover, focus-visible, and disabled states declared
- [ ] Links underlined by default; color alone is never sufficient
- [ ] Every button variant has **default-state distinction** (fill, border, or distinct text colour) — no hover-only affordance
- [ ] Ghost buttons have a default fill (e.g. `bg-panel-hover`) — never `background: transparent`
- [ ] Inputs in `:focus` change `border-input` to `border-input-focus` **and** show the `focus-ring` outline
- [ ] Informational sections do not mimic button affordances (pill radius, fill, ring)
